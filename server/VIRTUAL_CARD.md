# 星言设备虚拟卡

## 当前实现

- 每个实名用户可以生成一张设备绑定的内部测试虚拟卡号。
- 16 位卡号使用 `9999` 内部测试前缀并通过 Luhn 校验，**不是真实 BIN**。
- 卡号以 AES-256-GCM 密文保存；安全码不落盘，由服务端密钥、卡 ID 和卡版本临时派生。
- 支持面容 / 设备密码验证后显示、冻结、解冻和更换卡号。
- 换号会增加卡版本并使旧卡号失效；离开页面、退后台或 60 秒后自动隐藏卡号和安全码。
- 每次签发、查看、冻结、解冻、换号都会进入审计日志。

## 明确边界

当前虚拟卡号只能在星言支付系统内部用于产品展示和流程测试：

- 不能用于 Visa、Mastercard、银联或其他外部卡组织。
- 不能提交给外部商户、订阅服务或广告平台。
- 不能作为真实银行卡绑定到支付宝、微信支付、Apple Pay 或 Google Pay。
- 服务端不会用该卡号发起任何外部扣款。

API 明确返回：

```json
{
  "scope": "internal-test",
  "issuerConnected": false,
  "notice": "星言内部虚拟卡号，不是 Visa / Mastercard，不能在外部商户使用"
}
```

## 接真卡组织前的硬性条件

1. 与持牌发卡机构、收单机构和卡组织签约，取得真实 BIN。
2. 卡号和令牌由发卡机构 HSM 或支付网络令牌服务签发，星言服务器不自行生成真实 PAN。
3. 完成 PCI DSS 范围评估；优先采用网络令牌化，避免本地保存 PAN/CVV。
4. 接入 3DS、风控、授权、清算、退款、拒付和逐日对账。
5. 设备认证必须使用 Apple App Attest / DeviceCheck 或等价的硬件证明，不能只信任客户端传入的 `verified`。
6. 更换卡号、冻结、查看完整卡号必须有服务端可验证的设备签名和二次授权。
7. 在独立测试机构完成授权失败、重复扣款、网络超时、离线、丢包和对账差异测试。

缺少任何一项，都不得对外宣称该卡号可用于真实支付。
